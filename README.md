# Система учёта коммерческих предложений

Консольное приложение для создания и хранения коммерческих предложений.
В ПР5 к нему добавлен веб-интерфейс на Django: страницы только показывают
данные, без форм создания и редактирования.

## Назначение

Приложение помогает вести клиентов, менеджеров и коммерческие предложения.
В браузере можно:

- открыть главную страницу и перейти в разделы;
- посмотреть список клиентов и карточку клиента;
- посмотреть список предложений и карточку предложения;
- увидеть клиента и менеджера, связанных с предложением;
- увидеть итоговую сумму, срок действия и статус предложения.

Добавление, поиск, согласование и отмена по-прежнему работают в консольной
версии.

## Используемые технологии

- Python 3;
- Django 5.2 — веб-фреймворк;
- HTML — разметка страниц;
- Bootstrap 5.3 — оформление страниц;
- pytest — автоматические тесты;
- flake8 — проверка качества кода.

## Целевая аудитория

Менеджеры по продажам и сотрудники небольших компаний, которые готовят
коммерческие предложения для клиентов.

## Предметная область

Основные объекты предметной области:

- клиент;
- менеджер;
- коммерческое предложение.

Клиент может получить несколько коммерческих предложений. Менеджер готовит
предложения. Предложение хранит ссылки на объект клиента и объект менеджера.
Номер предложения должен быть уникальным. Отменённое предложение остаётся в
списке, но не учитывается как активное при расчёте статистики.

## Основные сущности

### Client — клиент

Объект `Client` представляет клиента, для которого готовится предложение.

Атрибуты:

- `id` — идентификатор клиента;
- `name` — название клиента.

Методы:

- `__str__()` — строковое представление клиента;
- `from_data()` — создание объекта `Client` из данных JSON.

### Manager — менеджер

Объект `Manager` представляет сотрудника, который готовит предложение.

Атрибуты:

- `id` — идентификатор менеджера;
- `name` — имя менеджера.

Методы:

- `__str__()` — строковое представление менеджера;
- `from_data()` — создание объекта `Manager` из данных JSON.

### Proposal — коммерческое предложение

Объект `Proposal` представляет коммерческое предложение.

Атрибуты объекта:

- `id` — идентификатор предложения;
- `number` — номер предложения;
- `client` — объект `Client`;
- `manager` — объект `Manager`;
- `amount` — исходная сумма;
- `discount_percent` — скидка в процентах;
- `created_date` — дата создания;
- `validity_days` — срок действия в днях;
- `status` — статус предложения.

Атрибуты класса, общие для всех предложений:

- `STATUS_PENDING` — ожидает согласования;
- `STATUS_APPROVED` — согласовано;
- `STATUS_CANCELLED` — отменено.

Методы:

- `final_amount` — итоговая сумма с учётом скидки;
- `get_expiration_date()` — дата окончания срока действия;
- `is_active()` — проверка, что предложение не отменено;
- `set_status()` — изменение статуса;
- `validate_discount()` — проверка корректности скидки;
- `__str__()` — строковое представление предложения.

Поиск предложения по идентификатору выполняет `find_proposal_by_id()`.
Эта функция нужна странице одного предложения.

## Взаимодействие объектов

Объект `Proposal` связан с объектами `Client` и `Manager`:

```text
Proposal
├── client → Client
└── manager → Manager
```

Поэтому из предложения можно сразу получить `proposal.client.name` и
`proposal.manager.name`. Два предложения одного клиента или одного менеджера
ссылаются на один и тот же объект.

В JSON сохраняются идентификаторы `client_id` и `manager_id`. При загрузке
по ним находятся объекты `Client` и `Manager`, и они передаются в предложение.

## Страницы веб-интерфейса

- `/` — главная страница, view-функция `index()`;
- `/clients/` — список клиентов из `data/clients.json`, view-функция `clients()`;
- `/clients/<int:client_id>/` — карточка клиента, view-функция `client_detail()`;
- `/proposals/` — список предложений из `data/proposals.json`, view-функция `proposals()`;
- `/proposals/<int:proposal_id>/` — карточка предложения, view-функция `proposal_detail()`.

Если клиент или предложение с указанным id не найдены, страница возвращает
код 404. Если адрес не совпал ни с одним маршрутом, срабатывает
`page_not_found()`. Своя страница 404 видна при `DEBUG = False`.

Общий каркас HTML собирает функция `page()`: кодировка, заголовок, Bootstrap
и меню. Остальные view-функции передают в неё только содержимое страницы.

## Основные операции

### Показываются на сайте

- просмотр списка клиентов;
- просмотр одного клиента;
- просмотр списка предложений;
- просмотр одного предложения;
- итоговая сумма, срок действия и статус предложения.

### Пока только в консоли

Эти операции есть с ПР3. На сайте они появятся позже, когда будут формы:

- добавление предложения;
- поиск по номеру, клиенту или менеджеру;
- проверка уникальности номера;
- согласование и отмена;
- фильтрация по статусу;
- сортировка по итоговой сумме;
- расчёт сводной статистики.

При добавлении предложения программа ищет клиента и менеджера по имени.
Если такой объект уже есть, используется он. Если нет, создаётся новый.

Отмена и согласование не удаляют предложение из списка, а меняют его статус
методом `set_status()`.

## Хранение данных

Данные по-прежнему хранятся в JSON-файлах:

- `data/clients.json` — клиенты;
- `data/managers.json` — менеджеры;
- `data/proposals.json` — коммерческие предложения.

При загрузке записи JSON преобразуются в объекты `Client`, `Manager` и
`Proposal`.
При сохранении объекты преобразуются обратно в данные JSON.

База SQLite, которую создаёт `migrate`, нужна только Django для служебных
таблиц. Предметные данные в неё пока не переносятся.

## Назначение модулей

### `main.py`

Консольная версия. Загружает данные, показывает меню и вызывает операции.

### `offers/`

Настройки Django-проекта:

- `settings.py` — настройки, список приложений, язык и часовой пояс;
- `urls.py` — маршруты верхнего уровня и обработчик 404;
- `asgi.py`, `wsgi.py` — точки входа для сервера.

### `homepage/`

Главная страница:

- `views.py` — функция `page()` и view-функции `index()`, `page_not_found()`;
- `urls.py` — маршрут `/`.

### `clients/`

Страницы клиентов:

- `views.py` — `clients()` и `client_detail()`;
- `urls.py` — маршруты `/clients/` и `/clients/<id>/`.

### `proposals/`

Страницы предложений:

- `views.py` — `proposals()` и `proposal_detail()`;
- `urls.py` — маршруты `/proposals/` и `/proposals/<id>/`.

Отдельное приложение для менеджеров не создавалось. Менеджер показывается
на карточке предложения через `proposal.manager`.

### `models/`

Классы предметной области и функции работы с ними:

- `clients.py` — класс `Client`;
- `managers.py` — класс `Manager`;
- `proposals.py` — класс `Proposal` и `find_proposal_by_id()`.

### `storage.py`

Загрузка и сохранение JSON. Преобразует JSON в объекты и объекты в JSON.
Веб-страницы вызывают `load_clients()`, `load_managers()` и `load_proposals()`.

### `utils.py`

Вспомогательные функции ввода консольной версии: `input_int()`,
`input_float()`, `input_date()`, `input_non_empty()`.

### `tests/`

Автоматические тесты объектов, методов и операций с коллекциями.

## Запуск приложения

Веб-версия:

```bash
python manage.py runserver
```

После запуска открыть в браузере `http://127.0.0.1:8000/`.

Консольная версия:

```bash
python main.py
```

Перед первым запуском сайта один раз выполнить:

```bash
python manage.py migrate
```
