# Система учёта коммерческих предложений

Консольное приложение для создания и хранения коммерческих предложений.
Веб-интерфейс на Django читает данные из SQLite через Django ORM.
Страницы используют HTML-шаблоны. Редактирование доступно в админке.

## Назначение

Приложение помогает вести клиентов, менеджеров и коммерческие предложения.
В браузере можно:

- открыть главную страницу и перейти в разделы;
- посмотреть список клиентов и карточку клиента;
- посмотреть список предложений и карточку предложения;
- увидеть клиента и менеджера, связанных с предложением;
- увидеть итоговую сумму, срок действия и статус предложения.

Добавление, поиск, согласование и отмена по-прежнему работают в консольной
версии.

## Целевая аудитория

Менеджеры по продажам и сотрудники небольших компаний, которые готовят
коммерческие предложения для клиентов.

## Предметная область

Основные объекты предметной области:

- клиент;
- менеджер;
- коммерческое предложение.

Клиент может получить несколько коммерческих предложений. Менеджер готовит
предложения. Предложение хранит ссылки на объект клиента и объект менеджера.
Номер предложения должен быть уникальным. Отменённое предложение остаётся в
списке, но не учитывается как активное при расчёте статистики.

## Основные сущности

### Client — клиент

Объект `Client` представляет клиента, для которого готовится предложение.

Атрибуты:

- `id` — идентификатор клиента;
- `name` — название клиента.

Методы:

- `__str__()` — строковое представление клиента;
- `from_data()` — создание объекта `Client` из данных JSON.

### Manager — менеджер

Объект `Manager` представляет сотрудника, который готовит предложение.

Атрибуты:

- `id` — идентификатор менеджера;
- `name` — имя менеджера.

Методы:

- `__str__()` — строковое представление менеджера;
- `from_data()` — создание объекта `Manager` из данных JSON.

### Proposal — коммерческое предложение

Объект `Proposal` представляет коммерческое предложение.

Атрибуты объекта:

- `id` — идентификатор предложения;
- `number` — номер предложения;
- `client` — объект `Client`;
- `manager` — объект `Manager`;
- `amount` — исходная сумма;
- `discount_percent` — скидка в процентах;
- `created_date` — дата создания;
- `validity_days` — срок действия в днях;
- `status` — статус предложения.

Атрибуты класса, общие для всех предложений:

- `STATUS_PENDING` — ожидает согласования;
- `STATUS_APPROVED` — согласовано;
- `STATUS_CANCELLED` — отменено.

Методы:

- `final_amount` — итоговая сумма с учётом скидки;
- `get_expiration_date()` — дата окончания срока действия;
- `is_active()` — проверка, что предложение не отменено;
- `set_status()` — изменение статуса;
- `validate_discount()` — проверка корректности скидки;
- `__str__()` — строковое представление предложения.

Поиск предложения по идентификатору выполняет `find_proposal_by_id()`.
Эта функция нужна странице одного предложения.

## Взаимодействие объектов

Объект `Proposal` связан с объектами `Client` и `Manager`:

```text
Proposal
├── client → Client
└── manager → Manager
```

Поэтому из предложения можно сразу получить `proposal.client.name` и
`proposal.manager.name`. Два предложения одного клиента или одного менеджера
ссылаются на один и тот же объект.

В JSON сохраняются идентификаторы `client_id` и `manager_id`. При загрузке
по ним находятся объекты `Client` и `Manager`, и они передаются в предложение.

## Страницы веб-интерфейса

- `/` — главная страница, view-функция `index()`;
- `/clients/` — список клиентов из SQLite, view-функция `clients()`;
- `/clients/<int:client_id>/` — карточка клиента, view-функция `client_detail()`;
- `/proposals/` — список предложений из SQLite, view-функция `proposals()`;
- `/proposals/search/` — предложения на выбранную дату, view-функция `proposal_search()`;
- `/proposals/statistics/` — число предложений по клиентам, view-функция `proposal_statistics()`;
- `/proposals/<int:proposal_id>/` — карточка предложения, view-функция `proposal_detail()`.

View-функция получает данные через ORM и передаёт их в контекст
`render()`. Список предложений поддерживает поиск, фильтры и сортировку.
`Paginator` выводит по два предложения на странице. Ссылки навигации
сохраняют параметры поиска, фильтрации и сортировки.

Если клиент или предложение с указанным id не найдены, шаблон показывает
текст «не найден», а view-функция возвращает код 404. Если адрес не совпал
ни с одним маршрутом, срабатывает `page_not_found()`. Своя страница 404
видна при `DEBUG = False`.

## Шаблоны

Общий каркас — `templates/base.html`. В нём подключены Bootstrap, свой CSS,
логотип и скрипт. Меню подключено через `{% include %}`. Страницы приложений
начинаются с `{% extends "base.html" %}` и заполняют блоки `title` и
`content`.

Ссылки в шаблонах строятся по имени маршрута, например
`{% url 'clients:detail' client.id %}`. Имя приложения задаёт `app_name`
в `urls.py` этого приложения.

На списках используются цикл `{% for %}`, ветка `{% empty %}` и фильтр
`length`. Если у клиента нет названия, фильтр `default` подставляет текст
«Без названия». Дату в виде дд.мм.гггг собирает SQL-функция `strftime`.

Статус предложения выбирается в
`proposals/includes/proposal_status.html`: «Отменено», «Согласовано» или
«Ожидает согласования».

Статические файлы лежат в `homepage/static/homepage/`:

- `css/style.css` — шапка, карточки и статус;
- `img/logo.png` — логотип;
- `js/main.js` — подставляет текущий год в подвал.

## Основные операции

### Показываются на сайте

- просмотр списка клиентов;
- просмотр одного клиента;
- просмотр списка предложений;
- просмотр одного предложения;
- поиск предложений на выбранную дату;
- поиск по номеру, клиенту и менеджеру;
- фильтрация по клиенту, менеджеру, статусу и дате;
- сортировка и постраничный вывод;
- число предложений у каждого клиента;
- итоговая сумма, срок действия и статус предложения.

### Консольная версия

Консоль поддерживает операции ПР3:

- добавление предложения;
- поиск по номеру, клиенту или менеджеру;
- проверка уникальности номера;
- согласование и отмена;
- сортировка по итоговой сумме.

При добавлении предложения программа ищет клиента и менеджера по имени.
Если такой объект уже есть, используется он. Если нет, создаётся новый.

Отмена и согласование не удаляют предложение из списка, а меняют его статус
методом `set_status()`.

## Хранение данных

Сайт использует базу `db.sqlite3`. Структуру таблиц создают миграции Django.
У каждой модели есть автоматически создаваемый первичный ключ `id`.

- `Client` в `clients/models.py` хранит название клиента.
- `Manager` в `proposals/models.py` хранит имя менеджера.
- `Proposal` хранит номер, сумму, скидку, дату создания, срок и статус.
  Номер уникален, сумма и срок положительны, скидка от 0 до 100.
- Поля `Proposal.client` и `Proposal.manager` — связи «многие к одному».
  `PROTECT` запрещает удалять клиента или менеджера с предложениями.
  Обратная связь доступна как `client.proposals` и `manager.proposals`.

Данные ПР7 переносятся командой `python manage.py import_pr7`. Она читает
`data/offers.sqlite` в режиме чтения, сохраняет ID и внешние ключи и добавляет
только отсутствующие ID. Для другого файла можно задать `--source`.
Команду используют при первом наполнении базы.

Папки `sql/` и `db/` содержат реализацию ПР7. На сайте этот слой заменён ORM.
JSON-файлы по-прежнему использует консольная версия.

### Запросы ПР9

В списке предложений `all()` строит исходную выборку. Отдельные `filter()`
ищут по номеру, нескольким полям, клиенту, менеджеру, статусу и диапазону
дат. `exclude()` скрывает отменённые предложения. Поиск по тексту использует
`iregex` с экранированием, для поиска по кириллице без учёта регистра. Списки клиентов и менеджеров для фильтра
получаются отдельными `values_list()` с `distinct()`.

Сортировка `order_by()` берёт поля из словаря допустимых вариантов.
`annotate()` и `F()` добавляют имя клиента в выборку карточек, а `values()`
оставляет поля для списка. Карточка предложения использует
`select_related("client", "manager")` и `get_object_or_404()`. Карточка
клиента использует `get()` и сумму предложений по обратной связи.

Статистика сохраняет клиентов без предложений. `Count()` считает их
предложения, а `aggregate()` вычисляет количество, сумму, среднюю,
минимальную и максимальную сумму без отменённых. Список клиентов
аннотируется через `Sum()` и показывает ноль, если предложений ещё нет.
Отдельная страница поиска сохраняет выборку ПР7 по дате. Список предложений
позволяет дополнительно исключить отменённые.

## Назначение модулей

### `main.py`

Консольная версия. Загружает данные, показывает меню и вызывает операции.

### `offers/`

Настройки Django-проекта:

- `settings.py` — настройки, список приложений, язык, часовой пояс и каталог `templates/`;
- `urls.py` — маршруты верхнего уровня и обработчик 404;
- `asgi.py`, `wsgi.py` — точки входа для сервера.

### `templates/`

Общие шаблоны проекта: `base.html`, страница 404 и меню `includes/navigation.html`.

### `homepage/`

Главная страница:

- `views.py` — `index()` и `page_not_found()`, обе вызывают `render()`;
- `urls.py` — маршрут `/`, `app_name = "homepage"`;
- `templates/homepage/index.html` — содержимое главной;
- `static/homepage/` — CSS, JavaScript и логотип.

### `clients/`

Страницы клиентов:

- `views.py` — `clients()` и `client_detail()`;
- `urls.py` — маршруты `/clients/` и `/clients/<id>/`, `app_name = "clients"`;
- `templates/clients/` — список, карточка и страница одного клиента.

### `proposals/`

Страницы предложений:

- `views.py` — список, карточка, поиск по дате и статистика;
- `urls.py` — маршруты `/proposals/` и `/proposals/<id>/`, `app_name = "proposals"`;
- `templates/proposals/` — список, статус и страница одного предложения.

Отдельное приложение для менеджеров не создавалось. Менеджер показывается
на карточке предложения через `proposal.manager`.

### `models/`

Классы предметной области и функции работы с ними:

- `clients.py` — класс `Client`;
- `managers.py` — класс `Manager`;
- `proposals.py` — класс `Proposal` и `find_proposal_by_id()`.

### `storage.py`

Загрузка и сохранение JSON. Преобразует JSON в объекты и объекты в JSON.
Её функции вызывает консольная версия.

### `utils.py`

Вспомогательные функции ввода консольной версии: `input_int()`,
`input_float()`, `input_date()`, `input_non_empty()`.

### `tests/`

Автоматические тесты объектов, методов и операций с коллекциями.

## Запуск приложения

В VS Code откройте папку проекта и выберите «Терминал → Создать терминал».
Для обычного запуска на этом Mac выполните:

```bash
cd ~/Desktop/framework
source .venv/bin/activate
python manage.py runserver
```

На новом компьютере сначала создайте виртуальное окружение командой
`python3 -m venv .venv` и активируйте его. Перед первым запуском установите
зависимости, примените миграции и загрузите исходные данные ПР7:

```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py import_pr7
```

Затем запустите `python manage.py runserver`. Для остановки нажмите Ctrl+C
в терминале, где работает сервер. Если порт 8000 занят, можно запустить
`python manage.py runserver 8001` и открыть `http://127.0.0.1:8001/`.

Сайт открывается по адресу `http://127.0.0.1:8000/`. Создание,
редактирование и удаление доступны в `/admin/` после входа администратора.
Если учётной записи ещё нет, её создаёт `python manage.py createsuperuser`.

Для демонстрации запросов на вкладке SQL запустите сервер с панелью отладки:

```bash
SHOW_DEBUG_TOOLBAR=1 python manage.py runserver
```

Консольная версия запускается командой `python main.py`.
